# Plug Detection Examples

Примеры диагностики физического подключения хэш-плат к контрольной плате через регистры FPGA.

## Описание

Драйвер предоставляет функции для опроса регистра `HASH_ON_PLUG` (ID 2), который содержит битовую маску состояния коннекторов хэш-плат. Каждый бит соответствует определенной цепи (Chain). Это позволяет быстро определить, какие платы физически установлены и готовы к работе, без необходимости проведения полной инициализации ASIC.

**Поддерживаемые цепи:**
- Chain 0 - 3 (для платформы V9 / Antminer S19)

## API Функции

```c
// Проверка статуса конкретной цепи
int fpga_check_plug_status(int chain_index, plug_status_t* status);

// Сканирование всех цепей (0-3) за один вызов
int fpga_scan_all_plugs(plug_status_t* statuses);
```

Структура статуса:
```c
typedef struct plug_status_s {
    int chain_index;   // Индекс цепи (0-3)
    int is_plugged;    // 1 = подключена, 0 = отключена
} plug_status_t;
```

## Примеры

### test_plug.c

Утилита для быстрого сканирования всех слотов хэш-плат. Выводит сводную информацию о количестве обнаруженных плат и детальный статус по каждой цепи.

**Компиляция:**
```bash
arm-linux-gnueabihf-g++ -static -std=c++11 -lpthread test_plug.c ../zynq7007_fpga_driver.c -o test_plug
```

**Использование:**
```bash
sudo ./test_plug
```

## Особенности реализации

1. **Регистровая маска**: Статус считывается из регистра `HASH_ON_PLUG`. Бит `N` этого регистра соответствует цепи `N`.
2. **Мгновенный отклик**: Проверка выполняется путем простого чтения регистра, что занимает микросекунды и не требует задержек на инициализацию шин.
3. **Диагностика неисправностей**: Полезно для определения обрывов шлейфов, проблем с питанием хэш-плат или неисправностей самих коннекторов на контрольной плате.
4. **Безопасность**: Функция `fpga_check_plug_status` включает валидацию входных параметров (`chain_index` должен быть в диапазоне 0-3).
